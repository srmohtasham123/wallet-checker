# wallet-checker

ابزار سبک برای چک کردن موجودی چند کیف‌پول روی چند شبکه، بدون نیاز به API key.

مستقیم با RPC عمومی هر شبکه صحبت می‌کند (`eth_getBalance` برای native، `eth_call` برای ERC-20، و یک موتور جدا برای توکن‌های SPL سولانا)، پس به هیچ سرویس واسطی (Etherscan/Blockscout/OKLink و...) وابسته نیست.

## ویژگی‌ها

- بررسی batch چند آدرس هم‌زمان (هر خط یک آدرس)
- **۲۳ شبکه** از پیش تنظیم‌شده (۲۲ شبکه EVM + سولانا)، گروه‌بندی‌شده به پرطرفدار/کم‌فعال
- **انتخاب چندشبکه‌ای هم‌زمان** — چک‌باکس روی هر شبکه یا کل یک گروه، همه با هم چک می‌شوند
- **پشتیبانی سولانا** — موتور RPC جدا (`rpc-solana.js`) که آدرس‌های base58 و توکن‌های SPL را می‌فهمد؛ اگر آدرس‌های EVM و سولانا با هم پیست شوند، هرکدام خودکار فقط روی شبکه‌ی متناسب با فرمتشان چک می‌شوند.
  موجودی SPL با مشتق‌کردن محلی آدرس Associated Token Account (PDA، بدون کتابخانه بیرونی) و یک درخواست دسته‌ای خوانده می‌شود — توضیح کامل در بخش «چرا سولانا روش متفاوتی لازم دارد»
- **Gravity Alpha** (chain 1625) با فهرست توکن‌های وریفای‌شده، همراه هشدار بازنشستگی شبکه
- منوی انتخاب شبکه به سبک iOS (باتم‌شیت با جستجو، آیکون و رنگ هر شبکه)
- هر شبکه ۱ تا ۴ RPC fallback مستقل دارد؛ اگر یکی پاسخ ندهد یا timeout بزند (۸ ثانیه)، خودکار سراغ بعدی می‌رود
- افزودن توکن ERC-20/SPL کاستوم از داخل رابط کاربری، با دکمه Select All / پاک‌کردن گروهی
- سه زبان: انگلیسی (پیش‌فرض)، فارسی، چینی
- جمع کل هر توکن/native در پایین جدول هر شبکه
- خروجی CSV، **خروجی Excel واقعی و استایل‌دار** (شیت خلاصه + یک شیت جدا برای هر شبکه، با هدر رنگی، border، و ردیف جمع کل بولد — مناسب برای باز کردن در Google Sheets/Excel)، خروجی گزارش خلاصه (Markdown)، و کارنامه تصویری قابل‌اشتراک‌گذاری (PNG با ارتفاع پویا که همه شبکه‌های دارای موجودی را کامل نشان می‌دهد، نه فقط چندتای برتر)
- جدول خلاصه بالای نتایج ("کجا واقعاً موجودی داری") + جمع‌شدن خودکار شبکه‌های صفر تا مجبور نباشید بین ده‌ها بخش خالی اسکرول کنید
- طراحی بهینه برای موبایل
- یک **قاعدهٔ بصری با یک معنا**: رنگ کهربایی فقط جایی ظاهر می‌شود که واقعاً موجودی پیدا شده. شبکه، ردیف، جمع کل و کارنامهٔ تصویری همه از همین یک رنگ برای همین یک معنا استفاده می‌کنند، پس بعد از جاروب‌کردن چند شبکه، کیف‌پول دارای موجودی در یک نگاه پیدا می‌شود
- بدون build، بدون dependency محلی — فقط HTML/CSS/JS خالص. تنها استثنا: دکمه "خروجی Excel" کتابخانه [ExcelJS](https://github.com/exceljs/exceljs) را از CDN (cdnjs.cloudflare.com) بارگذاری می‌کند، چون نسخه رایگان کتابخانه‌های جایگزین (SheetJS) قابلیت رنگ/border ندارند. این تنها وابستگی خارجی پروژه است و فقط هنگام کلیک روی آن دکمه لود می‌شود.

## شبکه‌های پشتیبانی‌شده (۲۳ شبکه)

همه Chain ID و RPC اصلی از chainlist.org، مستندات رسمی Solana، و مستندات هر شبکه گرفته شده‌اند. آدرس‌های USDC از [مستندات رسمی Circle](https://developers.circle.com/stablecoins/usdc-contract-addresses)؛ آدرس توکن‌های Gravity از مستندات خودش و با `eth_call` روی همان زنجیره وریفای شده‌اند.

**پرطرفدار:** Ethereum · BNB Smart Chain · Base · Arbitrum One · Avalanche C-Chain · Polygon PoS · OP Mainnet · Gnosis Chain · Linea · zkSync Era · opBNB · Scroll · Polygon zkEVM (در حال منسوخ‌شدن) · Xai Network · **Solana** · Gravity Alpha (در حال بازنشستگی)

**کم‌فعال/تخصصی:** Soneium · Taiko · Mantle · Cronos · Celo · Sonic (جانشین Fantom) · Moonbeam

### همهٔ RPCها از داخل مرورگر تست شده‌اند

این ابزار کاملاً در مرورگر اجرا می‌شود، پس هر endpoint باید دو شرط داشته باشد که تست سادهٔ `curl` نشانشان نمی‌دهد: باید هدر CORS برگرداند و نباید API key بخواهد. همهٔ endpointهای `chains.js` با هدر `Origin` واقعی تست شدند. در همین بازبینی چند مورد مرده پیدا شد:

| Endpoint | مشکل |
|---|---|
| `eth.llamarpc.com` و بقیهٔ `*.llamarpc.com` | خطای HTTP 525 و بدون هدر CORS — قبلاً RPC **اول** Ethereum و Base بود |
| `rpc.ankr.com/*` (۹ شبکه) | حالا `Unauthorized: You must authenticate your request with an API key` می‌دهد |
| `polygon-rpc.com` | خطای 401 |
| `cloudflare-eth.com` | `Cannot fulfill request` |
| `rpc.api.moonbeam.network` | در دسترس نیست |
| `mainnet.rpc.rarichain.org`، `rpc.redstonechain.com`، `rpc.superposition.so` | DNS دیگر resolve نمی‌شود |

سه شبکهٔ RARI Chain، Redstone و Superposition کاملاً حذف شدند: Redstone در مه ۲۰۲۶ خاموش شد، RARI Chain در حال sunset است، و دامنهٔ Superposition از دسترس خارج شده. نگه‌داشتنشان فقط خطای دائمی RPC تولید می‌کرد.

## چرا سولانا روش متفاوتی لازم دارد

دو مشکل مستقل باعث می‌شد سولانا از مرورگر کار نکند، و هر دو باید حل می‌شدند:

۱. **`api.mainnet-beta.solana.com` هر درخواست مرورگری را با HTTP 403 رد می‌کند.** به هر درخواستی که هدر `Origin` داشته باشد 403 می‌دهد — هر origin، حتی `localhost` — در حالی که همان درخواست بدون آن هدر 200 می‌گیرد. مستندات خود سولانا 403 را «سایت شما بلاک شده» توصیف می‌کند. fallback دوم یعنی `solana.drpc.org` هم روی پلن رایگان مرده بود. هر دو با endpointهایی جایگزین شدند که از مرورگر کار می‌کنند.

۲. **`getTokenAccountsByOwner` روی تقریباً همهٔ endpointهای بدون کلید بلاک است.** publicnode می‌گوید `Indexed requests require a personal token`، solanatracker می‌گوید `Method getTokenAccountsByOwner is not allowed`، و `getProgramAccounts` با کد 410 غیرفعال است. یعنی حتی با RPC سالم، خواندن موجودی SPL با این روش ممکن نیست.

راه‌حل این است که به‌جای پرسیدن «چه حساب‌های توکنی این آدرس دارد؟» از سرور، **آدرس حساب را خودمان محلی مشتق کنیم**. هر توکن SPL برای هر مالک دقیقاً یک Associated Token Account استاندارد دارد که آدرسش قطعی است:

```
ATA = findProgramAddress([owner, tokenProgram, mint], ATA_PROGRAM_ID)
```

فایل `rpc-solana.js` مشتق‌سازی PDA را (شامل SHA-256، base58، و چک on-curve روی ed25519) بدون هیچ کتابخانهٔ بیرونی پیاده می‌کند، اول هر mint را می‌خواند تا decimals واقعی و token program مربوطه را بفهمد، و بعد همهٔ حساب‌های مشتق‌شده را در یک فراخوانی `getMultipleAccounts` می‌خواند. یک مزیت جانبی: هزینه دو round trip است، مستقل از تعداد توکن‌ها، و decimals از خود زنجیره می‌آید نه از کانفیگ دستی.

`test-solana.mjs` این را با دادهٔ مرجع روی زنجیره می‌سنجد — فایل‌های واقعی پروژه را لود می‌کند، آدرس‌های مشتق‌شده را با حساب‌هایی که مستقل از زنجیره خوانده شده‌اند مقایسه می‌کند، و مقادیر دقیق موجودی را assert می‌کند. اجرا با `node test-solana.mjs`.

## اجرا

هیچ نصبی لازم نیست. کافی است `index.html` را با یک سرور استاتیک ساده باز کنید (برای جلوگیری از مشکلات CORS در برخی مرورگرها):

```bash
python3 -m http.server 8000
# سپس در مرورگر: http://localhost:8000
```

یا مستقیم فایل `index.html` را در مرورگر باز کنید، یا روی GitHub Pages / Vercel میزبانی کنید.

## افزودن شبکه جدید

در `chains.js`، یک ورودی جدید به آبجکت `CHAINS` اضافه کنید:

```js
mynetwork: {
  id: "mynetwork", name: "My Network", group: "popular", // یا "niche"
  chainNumericId: 123, nativeSymbol: "TOKEN", icon: "●", color: "#c9a15a",
  rpcUrls: ["https://rpc.example.com", "https://rpc2.example.com"],
  defaultTokens: [{ symbol: "USDC", address: "0x...", decimals: 6 }],
},
```

## افزودن زبان جدید

در `i18n.js`، یک بلوک جدید به `TRANSLATIONS` با همان کلیدهای بلوک `en` اضافه کنید، و یک دکمه در `.lang-switch` داخل `index.html`.

## محدودیت‌های شناخته‌شده

- RPCهای عمومی گاهی rate-limit می‌شوند؛ برای استفاده سنگین، RPC اختصاصی جایگزین کنید. هر شبکه در منوی انتخاب، فیلد **RPC اختصاصی** هم دارد (آیکون ⚙) که همیشه اول امتحان می‌شود.
- آدرس قرارداد توکن‌های پیش‌فرض باید قبل از استفاده در محیط حساس، از منبع رسمی هر شبکه verify شوند. decimals توکن‌های سولانا از خود زنجیره خوانده می‌شود پس کهنه نمی‌شود؛ decimals توکن‌های EVM هنوز از `chains.js` می‌آید.
- **Gravity Alpha (L2، chain 1625) در حال بازنشستگی است** — باید دارایی‌ها قبل از ۱ نوامبر ۲۰۲۶ به اتریوم برگردند و زنجیره دسامبر ۲۰۲۶ unsettle می‌شود. جانشین آن Gravity Mainnet (L1، chain ID 127001) است که آدرس توکن‌های متفاوتی دارد.
- این ابزار فقط موجودی لحظه‌ای را می‌خواند؛ مانیتورینگ خودکار/نوتیفیکیشن (مثلاً تلگرام) نیاز به یک سرویس جدا (cron/سرور) دارد که در این نسخه پیاده نشده است.
